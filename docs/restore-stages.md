# Этапы рестора ВМ (справочник по прогонам 13/14a–14g)

Полная цепочка фаз, которую проходит гость от старта машины до бута новой iOS.
Тайминги — реальные, из логов прогонов (скорость заливки ~0,055–0,083 %/с).

### Класс 3: краш процесса в уборке QEMU (после Done)

Сигнатура: тред `worker` (тред-пул блочного IO QEMU), SIGSEGV SEGV_ACCERR
«исполнение неисполняемой памяти», pc=lr в анонимной памяти, 1 кадр.
Регистры совпадают от вылета к вылету. Случается после `Stage.Done`, когда
QEMU уже умирает по QMP quit: `qemu_cleanup`/RCU/тред-пул в этом же процессе
падают сами (ср. комментарии в `qemu_bridge.c`: «второй qemu_init требует
свежий образ библиотеки», «call_rcu живёт вечно... порча кучи, SEGV»).
Человек видит: 100 % → меню → уведомление висит ~минуту → вылет на лаунчер.

**Фикс:** после `waitForPatcher()` сессия не зовёт `shutdownMachine`, а через
5 с гасит процесс целиком (`ProcessRestart.killAndReopen`) — будильник возвращает
приложение, данные рестора уже на диске. Тот же механизм, что у
`TazikEngine.killEmulator` («QMP не отвечает»).

## Корень смертей и фикс (720c422)

1. Перенос IN (эп 0x81 = dwc3 ep4) отдаёт все буферы, но LST в последнем TRB не было → модель не даёт XFERCOMPLETE и молчит.
2. На 30-й секунде XNU стреляет `AppleUSBXDCI::endpointIOTimerExpired` — драйвер гостя клинит эп навсегда (больше не ставит IN-переносы: `xfer=0x0`, диаг 341 с).
3. Гость крутит пустой цикл (CPU 100–200 %), сокет не читает, окно хоста наполняется → patience 900 с → разрыв → `emptyTheDisk()` стирает root → перезаливка с нуля.

**Фикс:** перенос с `count==0 && buffers empty` после 5 с грейса (`exhausted_at`) получает честный XFERCOMPLETE (данные уже доставлены) + освобождение; перед завершением — refetch кольца (звонок мог обогнать UPDATEXFER). Счётчик `xc#=` в диаг эпов. 60-секундная тихая чистка осталась бэкстопом.

## Диагностика вживую

- Диаг эп4: `grep -a "ep4.nr=2" files/emulator.log` — счётчики `sx#/rej#/ex#/ux#/uxf#/uxr#/uxnc#/xc#/nak#/ok#`, `why=`, `last_td=...(Ns)`.
- `xc#>0` — фикс сработал (честный XFERCOMPLETE отправлен).
- `endpointIOTimerExpired` в `files/guest-console.log` — смерть драйвера гостя (маркер поражения).
- CPU гостя: 100–200 % = жив/пашет; единицы = мёртв; D-нити = блок на диске.
- Пульс `тишина N с` — фаза без процентов (норма для этапов 5, 8, 10).
- Патience канала 900 с (bulkOutPatience): при истечении — разрыв → RestoreSession заново → emptyTheDisk → полная перезаливка.
